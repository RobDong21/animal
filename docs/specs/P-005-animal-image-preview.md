# P-005: Animal Image Replacement Preview

## Status

Approved for engineering — preview phase only.

## Problem

Live testing found that several animal images contain collages, groups, overlapping animals, or subjects that are too small to recognize. These weaken the one-word, one-animal vocabulary relationship.

## Goal

Prepare legally documented, optimized 4:3 WebP previews for comparison without changing the production animal assets.

## Non-goals

- Replacing production assets before product approval
- Sourcing the eight unresolved marine animals in this phase
- Using generated animal images
- Changing gameplay, layout, or animal data other than temporary preview metadata
- Committing downloaded source originals

## Licensing policy

- Accept only images explicitly identified as **CC0** or **public domain** on the exact source page.
- Do not accept CC BY, CC BY-SA, fair use, non-commercial, editorial-only, or unclear licenses.
- Recheck the exact source page at download time.
- Record animal ID, source page, creator or agency, license, license URL or rights statement, original dimensions, retrieval date, and modifications.
- Preserve provenance even when attribution is not legally required.
- Download the original-resolution file, not a Wikipedia summary thumbnail.

## Preview workflow

1. Create a machine-readable preview manifest containing the approved candidates and crop-only items.
2. Download candidate originals into a temporary, untracked staging directory.
3. Add a reusable Sharp-based animal image optimization script.
4. Support a per-image focal point or crop position in the manifest; do not rely on one automatic crop for every animal.
5. Produce proposed files as `{animal-id}.webp`.
6. Resize to 1200×900 using a 4:3 cover crop without upscaling.
7. Encode as WebP at approximately quality 80 and remove unnecessary embedded metadata.
8. Produce a side-by-side current-versus-proposed review artifact at the actual game display ratio.
9. Report output dimensions and file sizes.
10. Do not overwrite `public/animals/`, update production paths, or delete JPGs during this phase.

## Visual acceptance criteria

Each proposed image must:

- Show one clearly dominant animal
- Make the intended vocabulary label unambiguous
- Show defining features and a recognizable silhouette
- Place the animal at approximately 60–80% of the frame where practical
- Avoid competing animals, collages, heavy overlap, text, and watermarks
- Remain recognizable at the actual in-game display size
- Use a clean 4:3 crop without cutting essential body parts
- Be emotionally appropriate for children aged 5–8
- Be factually representative of the generic animal label

Close-up or unusual candidates such as Pig, Horse, Sheep, Whale, Monkey, Vulture, and Crocodile require particular scrutiny and may be rejected during preview review.

## Preview acceptance criteria

- [ ] All 29 candidate source pages are rechecked against the CC0/public-domain policy.
- [ ] Provenance metadata is captured for every downloaded candidate.
- [ ] Six crop-only images are attempted and failures are reported.
- [ ] The eight unresolved images remain unchanged.
- [ ] Every proposed preview is a 4:3 WebP no larger than 1200×900.
- [ ] No image is upscaled.
- [ ] Every proposed image passes the visual acceptance criteria or is clearly marked rejected.
- [ ] Current and proposed images can be compared side by side at game size.
- [ ] Production animal images and code references remain unchanged.
- [ ] No downloaded original is staged for commit.

## Promotion phase

Promotion requires separate product approval after reviewing the previews. Engineering may then replace approved assets, update references to `.webp`, create the permanent source manifest, remove superseded files, and run asset validation.
